# Separate simulator Health source

This simulator-only helper creates a distinct Health source for Lumen's real SDK inclusion tests. It has no Lumen app-group access. It is excluded from the Lumen project and Release products.

Build with `zsh scripts/health-source-fixture/build.sh`. The single reusable output is `/tmp/LumenBatch43HealthSource/LumenHealthSourceFixture.app`. The build embeds simulated HealthKit/application identity entitlements in `__TEXT`; its ad-hoc signing entitlements stay empty, matching Xcode's simulator layout. Signed device entitlements cannot substitute for this layout.

Install only on the dedicated Lumen test simulators, using their explicit UUID with `xcrun simctl install`. Never use a physical device. Launch the helper bundle `com.dbakp.lumen.fixture.health-source` with exactly two arguments: `seed`, `seed-measured`, `inspect` or `cleanup`, followed by a fresh run UUID. Use `simctl launch --terminate-running-process` between operations. First seed of each dataset requires the simulator's Health permission sheet; all requested categories concern this isolated synthetic test workflow.

Each run writes `Documents/health-source-<UUID>.json` inside the helper's own container. Keep that ledger through cleanup. Each sample UUID is persisted before saving, so even a partial save has a declared identity. Existing ledgers cannot be overwritten by seeding. Cleanup validates the ledger and queries only the helper's own source plus the exact run tag, then checks UUID/type/value/date before removing those samples. It refuses unexpected matches. Never delete the helper or its data container while an uncleaned run exists.

The ten samples represent two observations per quantity: water 150+250 mL, food energy 125+225 kcal, protein 8+12 g, carbohydrates 15+25 g and fat 5+7 g. Save the seeded and independently relaunched inspect readbacks before cleanup; retain the cleanup and post-cleanup readbacks too. A missing query result is not a claim of read permission. These helper checks do not establish that Lumen queries or commits these values: that requires a separate real app flow, matching source/window evidence, exact file preservation and test-sample cleanup.

`seed-measured` uses a separate V2 tag and dataset ledger for 22 observations: two per steps, active energy, resting energy, resting heart rate, HRV, oxygen saturation, weight, breathing rate, VO₂ max, heart rate and body fat. Expected totals are 240 steps, 50 active kcal and 150 resting kcal; heart-rate average is 72 bpm. Expected latest values are 61 bpm resting heart rate, 42 ms HRV, 98% oxygen, 71.25 kg, 17 breaths/min, 44 mL/(kg·min) VO₂ max and 23% body fat. Actual latest sample timestamps must match their ledger; query windows must not substitute for those timestamps. Stand hours and exercise time are not seeded by this dataset. V1 nutrition ledgers remain readable and cleanable; `inspect` and `cleanup` use each ledger's validated dataset, never a generic type-wide deletion.

`inspect-lumen <run UUID>` is a separate read-only operation. Before running it, copy a bounded `lumen-owned-<UUID>.json` manifest into the helper's Documents directory. Version 1 names the run, Lumen's exact journal owner, source `com.dbakp.lumen`, and six rows (water plus calories/protein/carbs/fat/fiber). Each row names the actual journal event, UUID local record ID, domain, metric, value and Foundation-encoded date. Derive these identities from two confirmed local UI records and the production journal; never invent delivered Health acknowledgements. The helper validates the manifest before requesting read access, then queries only the exact sync/owner/event/local-ID metadata conjunction. Every returned sample must match Lumen's source, quantity, date and sync version. The report includes observed sample UUIDs, but performs no Health save, delete or journal acknowledgement. Empty or partial reads remain inconclusive about permission. Local Undo/Delete and the production adapter perform cleanup; inspect again independently to check disappearance. Neither successful compilation nor an empty report establishes the full source-accounting case.
# Recorded-zero extension (helper version 4)

`seed-zero-nutrition RUN_UUID` creates one actual zero-valued SDK sample for each of water, food energy, protein, carbohydrates and fat. This uses a distinct `zeroNutrition` dataset, ledger version4 and `LumenZeroSourceFixtureV4` metadata key. Existing nutrition version1, measured version2 and read-only Lumen inspector manifests retain their original validation and cleanup boundaries. No new quantity types or Lumen data access are added.

Predeclare the expected Lumen query and cleanup before running. Actual zero saves can fail or query differently; preserve those outcomes rather than converting them to a pass. Keep exact UUIDs and use `inspect RUN_UUID` and `cleanup RUN_UUID` for this dataset, followed by a separately relaunched inspection. Only use a named disposable verification simulator.
