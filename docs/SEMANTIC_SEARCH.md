# Local related-topic search · Batch 19

Batch 19 adds optional English related-topic ranking to the native Assistant and Library source disclosures. The implementation and scoped delivery checks are complete, published as `f957f1bec644e8da8e55da0b2feee390c78839d8` with matching GitHub remote read-back. The full product goal remains active.

## Product contract

Preserve keyword search, source fingerprints, exact saved excerpts, consent checks, independent reply references, cancellation and the four-passage/two-per-document limits. Add optional English related-topic ranking on this iPhone. Similarity identifies a possible topic; it does not establish that an excerpt answers the question, negation is equivalent, a measurement is current or a clinical conclusion is valid.

The model control is off by default, with explicit download-and-enable, actual received/total transfer size, separate preparation/cleanup states, cancellation and deletion. No question or record text goes to the model host. The selected AI provider may still receive the existing health/conversation context and selected shared excerpts. Search on the device does not make the whole assistant local. No account or provider credit is required for local ranking.

## Pinned assets and storage

The selected development input is the [haihengh Core ML conversion](https://huggingface.co/haihengh/all-MiniLM-L6-v2-coreml/tree/c683f20435a63c9884472f5de9f56865e865fd99) of [sentence-transformers/all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2). The source cards declare Apache-2.0. Model and vocabulary attribution/license are retained in app resources. This is a general English retrieval model, not a validated clinical model. Conversion accuracy claims belong to the conversion author; Lumen has not independently established PyTorch weight parity.

Three fixed files total **45,012,149 bytes**. `SemanticModelPackage` pins the repository revision, paths, exact sizes and individual SHA-256 values; no downloaded manifest can select a new path or model. The 231,508-byte vocabulary is bundled and independently hash-checked. Preparation requires 250 MB of free space. The private stage contains source plus compiled weights temporarily; after self-check and encoder stop it discards the downloaded package, retaining only the compiled model and a bounded file-hash receipt. Files live separately from the swappable local-data directory and are excluded from backups. There is no persistent vector or duplicate-text index; the encoder cache is private RAM, bounded by 8,192 entries and eight million Float values, purged against the current shared source snapshot and cleared when the encoder stops.

`SemanticSearchService` never starts a download from a question or at launch. Download and enable are an explicit Settings action. Turning off invalidates outstanding search leases, cancels loading and stops the encoder while keeping generic weights. Delete and regular data erasure invalidate work first, await active installation/loading/inference, then remove the owned model directory. A pending-removal preference permits retry after termination. A new installation removes only UUID-named owned abandoned stages before starting; other names and symlinks are not traversed. File receipts bind cleanup to the installation's UUID so a late cancellation cannot remove a newer install. Hash verification detects changed local assets; the receipt is private local metadata, not an independently signed model attestation.

### Core ML runtime copies

The first on-disk erase audit found **901,022,648 bytes** in the dedicated app's cache despite the managed model directory being absent. Twenty CPU program packages accounted for 900,464,640 program bytes, plus descriptors. Every program contains eight disjoint 64-byte blocks from the fully hashed pinned weights. This was a storage defect, not private vector persistence; the packages are runtime-compiled model programs.

`MiniLMRuntimeCache` now checks only the current app's observed E5 cache namespace. It requires the expected bounded build/hash/package hierarchy, regular nonsymlink files, one bounded CPU program and all eight pinned weight fingerprints. Partial matches, redirected directories and unrelated packages/Metal caches are preserved. It limits scanning to 32 build directories, 2,048 model directories per build, 512 packages and 4 GiB per pass; each package is limited to 128 entries/128 MB. Only an emptied parent of a removed matching package can also be removed. This observed runtime layout is not a cross-version Core ML contract; unknown layouts remain untouched and physical-device validation stays open.

Fresh installation clears stopped old copies before the free-space check, then clears the self-check's runtime copy after that encoder stops. Final loading creates the reusable installed-path cache. Delete/erase and cancelled/failed installation cleanup await workers/encoders before removing recognized copies. Cache clearing has its own indeterminate native state and Cancel control; it is not portrayed as received network bytes. Keyword search remains available.

The corrected remote/erase native case passes **244.671 seconds**. Subsequent filesystem read-back finds no managed model directory, no direct temporary compiled model and **no CPU program caches**. The app cache contains only the preserved Metal files, **496,648 bytes**, a measured logical-file reduction of 900,526,000 bytes from the earlier audit. Exact scope and limits are in `cache-investigation.json` and `erasure-readback.json`. These figures describe the dedicated synthetic app, not all system caches or physical-iPhone storage. Apple's [cache-directory documentation](https://developer.apple.com/documentation/foundation/filemanager/searchpathdirectory/cachesdirectory) describes the general discardable-cache location; the model-specific ownership checks are Lumen's measured implementation.

Actual transfer bytes drive progress; checking, native compilation/self-check and stopping are separate indeterminate states. Native compilation cannot be assumed interruptible, so cancellation waits for the worker before deleting its files. General English ranking uses the measured CPU path. Related-topic selection and actual comparison coverage are retained with each reply, backup and readable export. Settings/source changes during a request prevent stale search results from being returned as the current reply. Previous independently saved references remain subject to the existing copy policy.

## Current backend

`MiniLMTokenizer` implements uncased BERT WordPiece preprocessing. Twenty fixtures match the independently loaded `tokenizers==0.22.1` reference with the pinned tokenizer file. Numbers, units, accents, special tokens, punctuation, controls and multilingual Unicode inputs are included. These establish selected tokenizer cases, not multilingual model quality. Every passage token is retained through overlapping 256-token windows; overlong questions use keyword search rather than a silently clipped model question.

`MiniLMEncoder` confines Core ML inference to an actor, validates feature shapes and normalizes finite 384-dimensional outputs. It uses the measured CPU path: the initial CPU-and-Neural-Engine probe produced an ANE compilation diagnostic, although Core ML returned a result. That diagnostic is retained in the investigation; the default was changed rather than suppressing it. `stop()` releases the model/cache and prevents retained leases from starting another prediction, allowing the owner to remove its files safely.

`RecordRetrieval.candidates` builds one bounded consent-filtered snapshot for both ranking paths. `HybridLibrarySearch` compares English questions against those exact source windows, visits within-document ordinals across records, uses a 12-second comparison budget, and retains explicit coverage/cache metadata. Keyword search still covers the bounded text index. Reciprocal-rank fusion retains the leading keyword hit and supplements it with topic matches above a provisional **0.42 cosine-similarity** threshold. This threshold is a ranking policy, not confidence or clinical validation. Cached input hashes prevent key reuse from returning vectors for changed input. Source selection methods are optional metadata for older conversation/backup decoding; model identities are historical identifiers, not paths to execute or permission to load a model.

Literal local lookup retains the full selected packet, at most four excerpts and two per document. It must not discard a later related-topic result after leading keyword matches; an actual-model check exercises the edema example following three keyword candidates. Source selection, real comparison coverage and uncertainty travel with JSON backups/readable recovery and referenced Markdown text. Older unrecorded selection stays explicitly unrecorded.

## Investigation and limits

The initial Apple `NLEmbedding` sentence/word probes are retained in `Design/native/semantic-search`. The sentence model ranked unrelated decoys above relevant fatigue/edema text in selected cases; nearby word examples included opposites. Those probes are not shipped as synonym substitutions. Apple's APIs are described in [NLEmbedding](https://developer.apple.com/documentation/naturallanguage/nlembedding) and [finding similarities](https://developer.apple.com/documentation/naturallanguage/finding-similarities-between-pieces-of-text).

The pinned Core ML model improves the tested sleep, fatigue and swelling comparisons but misses the tested iron-stores/ferritin relationship. Both that miss and the unrelated iron-pan comparison remain in the report. No comprehensive English, medical, multilingual, physical-device, energy, storage-pressure or release benchmark follows from these examples. The initial Mac CPU probe observed about112 MB maximum resident size and0.131 seconds for18 vector predictions; this is not an iPhone performance claim.

The larger **nine-query, eleven-document synthetic diagnostic** in `Design/native/semantic-search/synthetic-quality-diagnostic.json` records both production keyword and hybrid selections, with all misses and unexpected results retained. Hybrid finds the expected contexts in eight cases versus six for keyword search; the iron-stores question still selects the kitchen record and misses ferritin. The swelling question retrieves the edema record as an additional fourth source while retaining three ankle records. Negation and laterality examples select multiple differently qualified records, showing why topic selection cannot stand in for reading an excerpt or establishing an answer. This small hand-authored diagnostic is not an independent benchmark, does not prove clinical suitability, and was not tuned by changing the threshold to meet a passing count.
