# Follow-up source finding · provider disconnection and route identity

Source inspection after the Batch41 content-authorization work identifies a separate provider/account boundary. This has not yet been reproduced with a controlled refresh and is not covered by the passing Library/personal-context cases. No live credential or provider request was used for this finding.

`LLMConnectionService.validOAuthToken()` awaits token exchange, then unconditionally writes the returned access token and expiry. `disconnectOAuth()` clears token/refresh/expiry and changes mode, but does not invalidate the suspended exchange. `LLMClient.route()` enters the OAuth branch before that await, then reads mutable endpoint/model settings after it. There is no captured account/configuration generation check on either the credential write-back or final route. Source therefore leaves a possible late credential write and provider submission after a disconnect or configuration change. The ordinary brain label also needs auditing against the actual compatible gateway/account route; the Batch41 synthetic label is not proof of live provider identity.

Declare and reproduce this boundary before repair: hold the shared production refresh/configuration preparation with synthetic credentials only, disconnect or replace the configuration, release it, and inspect actual credential storage plus outgoing requests. Include unchanged, refresh failure, mode/endpoint/model/client changes, change-then-revert and reset controls. Re-authorizing old health context from new configuration is not equivalent to validating its original route.

A repair must preserve the original request/account/configuration identity through refresh write-back and final submission, prevent late credentials from restoring a disconnected account, and capture a factual provider label. Test actual checked credential outcomes and storage failures; do not log tokens, authorization headers or arbitrary prompts. Verify live OAuth/physical-device behavior separately when only synthetic exchange evidence is available.

Prioritize this bounded authorization audit after Batch41 publication, then continue the already-declared durable Health and acknowledged Watch work in next-audit.md. Evidence-support, clinical/provider/device, accessibility, performance, privacy and distribution gates remain part of the full product goal.
