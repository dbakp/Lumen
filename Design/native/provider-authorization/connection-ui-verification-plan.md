1. Open the original custom API-key fixture. Choose OpenAI and Google AI Studio presets and verify displayed draft endpoint/model values without changing the actual saved tuple/revision. Do not send a request to those public preset destinations. Return to Custom before saving fixed loopback changes.
2. Edit API endpoint/model and preference, save, reopen and compare actual fields plus independent saved tuple classifications/hash. Credentials remain unchanged. Test-route requests are already exercised through the dedicated loopback caller endpoint; do not repurpose an incompatible chat endpoint as a connectivity fixture.
3. Switch the draft to Google OAuth and verify that the saved API mode/tuple stays unchanged until Save. Verify client ID, requested scopes, endpoint and model fields. Edit fixed synthetic values. Sign-in/Test are disabled while the draft is dirty. Save/reopen verifies the complete new tuple, with the previous OAuth account bytes retained but rejected for mismatched client/scope. Do not open a real browser or imply that synthetic sign-in proves a registered/live Google client.
4. Switch to Apple/built-in, verify the change is draft-only until Save, then verify external routing is off while existing saved API/OAuth credentials remain until removal. Reopen and switch back to API key; prior endpoint/model/key/preference must remain. Remove AI credentials at the end and verify API/OAuth cleanup.

Add only bounded synthetic classifications/digests needed to independently verify fields. Never return arbitrary secrets or personal history in fixture reports.
