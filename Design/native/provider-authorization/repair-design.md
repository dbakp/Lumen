# Repair implementation sequence

BaselineR3 supplies actual evidence before repair: all ten scenarios complete, ten token exchanges and nine chat packets match an independent host audit, with no hold timeout. Disconnect and mode/client/scope/revert still send; endpoint/model mutations affect the waiting packet. The provider-related reset operations remove credentials/defaults, then refresh recreates access/expiry while no chat endpoint remains. Failed refresh falls back to an expired access token. These are observed defects, not accepted behavior.

1. Add checked Keychain read/update/add/delete operations with typed status outcomes. Update an existing item rather than deleting it before replacement; distinguish missing from unavailable/corrupt. Preserve other services and legacy migration while preventing a failed migration from deleting its only source. Native tests must inspect real stored values, and label explicitly injected status failures separately from actual device errors.
2. Use an atomic OAuth credential record binding account identity, client/scope, access/refresh tokens and expiry in one Keychain item. Declare and test migration from separate legacy entries; disconnect must remove every legacy source to prevent rehydration. Failed credential removal must disable routing and expose a retry, including across relaunch. Do not claim a multi-key transaction where none exists.
3. Rotate a shared request-authorization generation on every committed routing/credential/preference intent, including change then revert. Reset and secret-erasure entry points must invalidate synchronously even outside the service actor. Snapshot settings plus credential/account identity; current values alone cannot detect a completed revert. Audit direct defaults writes and restore paths. Coalesce same-account refreshes or define equivalent ownership; late refresh/login callbacks must validate before both credential commit and return.
4. Capture provider authorization before the first suspension of a coach request, including background Library search. Carry it through credential resolution, serialized request/session preparation and final Foundation handoff. Apply the same contract to compatible scheduled plans, extraction/vision and connectivity checks. Invalidation must not retry an earlier health packet against a new account/route. Already-submitted input cannot be recalled; reject stale responses with factual caller outcomes.
5. Capture a factual route label with the accepted reply. Current Brain.openAIKey's static OpenAI wording is insufficient for compatible/OAuth gateways. Use the captured host/method or a verified exact preset mapping; omit credentials, path queries and invented account identity. Update capability/settings/caller copy consistently rather than attributing a reply from mutable completion-time settings.
6. Replace key-on-every-keystroke commits and onAppear preset rewriting with an explicit checked draft save/remove flow. Opening settings must leave the original account/route unchanged. Preserve drafts on failed save, show retryable errors, and protect dismissal of unsaved edits. Do not silently reduce the service to OpenAI-only to avoid verifying the existing compatible/OAuth contract. New native UI must use the same continuing App Designer Pro critic and actual normal/largest main/compact captures.
7. Validate sign-in attempt identity/state/PKCE/callback and cancellation independently. Current code is not proof of live Google iOS client/redirect compatibility. Consult current primary provider documentation before choosing a supported live contract; synthetic callback/exchange tests must never be presented as real account acceptance.

Use the frozen baseline snapshots to reproduce old behavior after production changes; do not leave a production legacy path enabled just to make baseline tests pass. Fixed native checks must inspect actual credential state, caller outcomes and independent wire packets across unchanged, disconnect, every configuration field, revert, reset, failed/overlapping refresh, key replacement, cached-token/final-preparation holds, stale login, and typed storage failures. Repeat Library/personal/transport regressions at exact boundaries; Release marker/Debug-positive audit and source identities precede application publication. Full-goal Health/Watch/evidence/device/accessibility/privacy/distribution work remains active afterward.
