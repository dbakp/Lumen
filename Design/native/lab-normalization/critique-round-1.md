## Five executable corrections

1. **Pair the original amount with its conversion.** In each Converted values group in current review and saved presentation (703/704/708/721/725/742), show “Reported: 12.00 g/dL” immediately with “Converted: 120 g/L”; the later group should show “Reported: 135.00 g/L” with “Converted: 135 g/L”. Keep the exact factor and actual assignment basis secondary in that same group. The full original sections should remain available. This is a presentation/provenance problem, not a claim that the shown arithmetic is wrong. The Batch 24 content contract already requires the pairing.

2. **State the limit of a name match before acknowledgement.** In 703/704/708/721/744, “Same reported name” is followed directly by “I checked the test identity”. Add the specified sentence immediately below the name-based choice: “Your match applies to this snapshot. No terminology equivalence was verified.” Include a factual equivalent in the captured review for either name-based basis. Do not add that sentence as though it describes a supplied-code match; keep the actual basis distinct. The general arithmetic/clinical boundary below the difference does not explain this specific identity decision.

3. **Repair the compressed limits copy.** In 707, the visible strings include “128 ASCII bytes;64 components;8 nested groups”, “powers±24” and “at most1,000,000,000”. Add the missing spaces and separate the limits into short lines or native reader paragraphs, for example “Maximum 128 ASCII bytes” and “Maximum 64 components”, retaining the exact implemented limits. Keep necessary syntax details in this dedicated reader; do not make the primary review carry them.

4. **Present exact factors as readable maths.** In 703/708/721/742, replace the visible “Exact factor: × 10^1 · from g/dL” with “Exact factor: ×10 · from g/dL” for this exact value. For other factors use properly typeset superscript exponents or an equally readable exact representation; do not round or change the underlying exact arithmetic. This also avoids the literal caret expression becoming very large body text at XXXL.

5. **Remove generated formatting marks from the native captured reader.** In 711, “## Reviewed unit conversion” is an app-generated section heading displayed as plain body content. Show “Reviewed unit conversion” as a native heading, or omit only the generated Markdown marker in this native presentation. Preserve the original report wording and the complete captured facts; an exported Markdown representation may retain its appropriate Markdown syntax.

These are the requested corrections for this round. The scorecard's portfolio routes do not request a new concept, imagery, icon, card system or animation.
